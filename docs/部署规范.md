# 部署规范

## 发布流程
1. 代码合并到 main 后，CI 自动构建 Docker 镜像并打上版本标签。
2. 镜像推送到私有仓库 `registry.example.com`。
3. 在 Kubernetes 集群中执行滚动更新（rolling update），分批替换旧 Pod。
4. 更新后做健康检查（/healthz 探针），连续失败则自动回滚到上一版本。

## 环境划分
- dev：开发环境，允许热更新。
- staging：预发布，数据接近生产，用于回归测试。
- prod：生产，变更需走审批。

## 回滚策略
每次发布保留最近 5 个镜像版本；出现异常优先回滚再排查，保证服务可用性优先。
